# Example session policy

This C0 fixture records decision boundaries for the supplied example
requirements. It does not create credentials, approval, execution rights or
authority to change a production system. Installed grants and current owner
decisions remain independently necessary.

## Delegated decisions

Agents may choose implementation structure, bounded investigation steps and
focused checks within the selected requirement and the available sandbox.
They may use the supplied synthetic examples and create reviewable candidates
in an authorized writable workspace. They must distinguish observed results
from hypotheses and proposed actions.

## Product decisions

Changes to the intended outcome, business meaning, acceptance thresholds, public
interfaces, source population or required data retention need an applicable
owner decision. An unresolved decision pauses affected work; unrelated work
with satisfied dependencies may continue. A decision record must identify its
scope and the requirement revision to which it applies.

## Review and completion

Inline review derives acceptance from the requirements before assessing a
candidate. It uses an independent session and the required checks. Holistic
review assesses the assembled candidate's intention, interfaces and operational
behavior. The workflow specifies the substantive-failure and nit thresholds;
those thresholds never convert an unmet requirement into a nit.

The examples route coordinated candidates to human review and direct results
back to their caller. Neither a successful model response nor a Sovite job's
completed state accepts the work or authorizes merge or deployment.

## Data and context

The supplied fixture files contain only C0 synthetic material. That label does
not apply to arbitrary repository contents, tool results or later task input.
Missing classification resolves to the installation's most restrictive class.
Restricted material requires a private model boundary.

Any declared transfer into a lower-class role or from a private source to a
public destination requires an installed output contract and an approved release
of the exact transformed content. A public reviewer receives a released review
context containing the permitted requirements and candidate material; it must
not receive the full restricted requirements or implementation transcript.

## Recovery

Retain requirement, policy, candidate, decision and evidence references across
session restarts. Reconcile an uncertain job using its existing identity before
creating another attempt. Do not repeat an external effect merely because its
response was lost.
